# C04 - 감사 로그와 오류 처리

## 1. 작업 목적
감사 로그 UI와 업데이트 영역 공통 오류 처리를 구현한다.

## 2. 반드시 먼저 읽을 문서
- 루트 또는 병합된 `AGENTS.md`
- `docs/update-server` 관련 문서
- `codex/update-server/WORK_STATUS.md`
- 현재 저장소의 실제 대상 파일 전체
- 감사 API 계약
- C03 결과

문서와 현재 코드가 충돌하면 임의 구현하지 말고 `Blocked`로 보고한다.

## 3. 작업 전 현재 상태 확인
- C03 Completed
- 현재 알림 패턴
- 로그아웃
- Client 중복 처리

## 4. 수정 허용 범위
- 감사 목록·릴리스 이력
- 오류 Helper
- 접근 캐시 무효화
- DTO·스타일

목록 밖 파일이 반드시 필요하면 이유와 경로를 먼저 보고한다.

## 5. 금지 사항
- 전체 ApiClient 대규모 변경
- 감사 수정·삭제
- 403에서 로그인 제거

## 6. 구현 요구사항
- 401 로그인 제거
- 403 로그인 유지·캐시 무효화
- 409 충돌
- 413 크기
- 503 인증서버 장애
- 읽기전용 서버 페이징

## 7. 오류 처리 및 안정성
- 빈 Body·역직렬화 실패 안전 처리

## 8. 빌드 및 테스트
- `dotnet build poscam.sln -c Release`
- 오류 테스트

실패 상태에서 다음 단계로 이동하지 않는다.

## 9. 완료 조건
- 일관된 오류
- 403 캐시 갱신
- 감사 읽기전용
- 빌드 성공

## 10. 완료 보고 형식
```text

- Completed / Blocked / Failed

- 경로: 변경 목적

- 결과:

남은 문제
- 컴파일 오류:
- 실제 동작 오류:
- 불필요한 중복:
- 다음 단계 선행조건:

정책 이탈 여부
- 없음 / 상세 내용
```

완료 시 `codex/update-server/WORK_STATUS.md`의 해당 단계만 갱신한다.
